一、OCR 识别提示词（模板）
--------------------------------------------------------------------------------
说明：{lang_hint} 在使用时可替换为「重点关注以下语言：中文、英文。」或留空。

【核心原则：禁止联想，只看图上字】

请识别这张图片中的文字内容。{lang_hint}

**⚠️ 严格执行：禁止联想、禁止补全、禁止推测**

1. **只能输出图片中实际可见的字符**，不要根据语义、语境、常识去"猜"或"补全"
2. **禁止行为**：
   - ❌ 禁止把形近字"纠正"成你认为正确的字（如图中是"厶"就输出"厶"，不要改成"么"）
   - ❌ 禁止把残缺字"补全"成完整字（如图中只显示一半就如实描述或标为不完整，不要猜完整形态）
   - ❌ 禁止根据句子通顺度改写（如"你用心写"不要改成"你用什么写"）
   - ❌ 禁止联想、推测、推理任何未在图中明确显示的内容
3. **必须行为**：
   - ✅ 图中是什么字形就按什么输出（包括错字、形近字、异体字、占位符）
   - ✅ 若某字只显示一部分或难以辨认，在 text 中如实写出可见部分，或在描述中说明"不完整/模糊"
   - ✅ 不确定的字符保持原样，不要替换成你认为"更合理"的字

请按以下 JSON 格式返回结果：
```json
{
    "text": "仅包含图片中实际可见的文字内容，一字不增不减不改",
    "languages_detected": ["检测到的语言1", "语言2"],
    "text_blocks": [
        {
            "content": "该块内实际可见的文字，不推测不补全",
            "language": "语言",
            "position": "位置描述（如：左上角、中间、底部等）"
        }
    ]
}
```

要求：
1. 只识别图中实际可见的字符，不联想、不补全、不纠错
2. 保持原有字形与排版，包括可能存在的错字、乱码、不完整字
3. 标注每段文字使用的语言
4. 若有多种语言混合，分别标注
5. 若某字符不完整或无法确认，在 content 中如实反映（如写可见部分或注明"不完整"）


--------------------------------------------------------------------------------
二、UI 检测提示词（发给 UI 检测模型 / 视觉模型）
--------------------------------------------------------------------------------
说明：这是「多语言 OCR Agent」里 UI 检测使用的完整提示词，可直接复制到星源，再粘贴待检测的截图，观察模型是否按该规则输出。

【⚠️⚠️⚠️ 关键任务：检测文字显示问题 ⚠️⚠️⚠️】

**🔴 证据原则（最高优先级，必须严格执行）**
- **只有图片中明确可见、可指出的证据**才能判定为问题；禁止推测、禁止联想、禁止"可能有问题"。
- 若某类问题在图中**无法直接看到**（如看不到截断、看不到乱码、看不到异常换行），则**不要**在 issues 中列出该项，并在 summary 中明确写"未发现"。
- **结论与证据必须一致**：若 summary 写"未发现任何问题"或"显示完美"，则 issues 必须为空、score 应为高分；若 issues 非空，则 summary 必须与问题列表一致，不得自相矛盾。
- 单行、单词、少量文字且显示完整时，若无截断/溢出/重叠/乱码等可见证据，应判为无问题，不得臆测"可能有换行问题"等。

**🚨 重要警告：如果你发现字符被截断但得分却是 100 分或接近 100 分，这是完全错误的！必须重新检查！**

**第一步：强制检查字符完整性（必须首先执行，不可跳过）**

这是最重要的检查步骤，必须在所有其他检查之前完成。如果你跳过这一步，检测结果就是无效的。

在开始任何其他检查之前，你必须立即执行以下操作：

1. **逐字符扫描**：从图片左上角开始，逐个检查每一个可见字符
2. **边缘检查**：对每个字符，检查其四个边缘：
   - 顶部边缘：是否紧贴图片上边界？如果是，字符顶部是否完整？
   - 底部边缘：是否紧贴图片下边界？如果是，字符底部是否完整？
   - 左侧边缘：是否紧贴图片左边界？如果是，字符左侧是否完整？
   - 右侧边缘：是否紧贴图片右边界？如果是，字符右侧是否完整？

3. **截断判断规则（严格执行）**：
   - 如果字符的**任何边缘**紧贴图片/容器边界，且该边缘的字符部分看起来不完整 → **立即标记为截断**
   - 如果字符的一部分在图片中不可见 → **立即标记为截断**
   - 如果文字行的最后一个字符看起来不完整 → **立即标记为行尾截断**
   - **【右侧裁切/容器过窄】**：若多行或多条文字均在**同一右边界**处结束（如侧栏、列表项），且可见部分像不完整单词或词组（例如仅显示 "Cov"、"Mont"、"Artic"、"Week"、"Read" 等，右侧紧贴容器或明显被切齐），则**必须**判为文字截断（容器过窄、右侧被裁切），严重程度 high。
   - **不要考虑"可能是什么字"，只看图片中实际显示的内容**；但若**可见内容本身**明显是"单词被从右侧切掉"（多条同风格、同右边界、短片段），即属截断。

4. **禁止行为（严格执行）**：
   - ❌ 禁止推测被截断字符的完整形态
   - ❌ 禁止因为"可能是什么字"而忽略截断
   - ❌ 禁止因为"整体能理解"而忽略截断
   - ❌ 禁止联想或补充任何内容

5. **如果发现截断**：
   - 问题类型：文字截断
   - 严重程度：high
   - 必须详细描述：哪个字符、哪个方向（左/右/上/下）被截断
   - 得分必须降低（有截断问题不能是 100 分）

**第二步：检查其他显示问题**

完成字符完整性检查后，继续检查：

需要检测的问题类型（必须逐一检查）：

1. **异常换行** - 严重程度通常为 medium 或 high
   - **单词中间被换行**：单词在不应该断开的地方被换行（如 "hel-\nlo"、"测-\n试"）
   - **不合理换行**：在标点符号前换行、在数字中间换行、在专有名词中间换行
   - **行尾单词分割**：单词被不恰当地分割到两行
   - **换行位置不当**：应该在某个位置换行但没有换行，或不应该换行的地方却换行了
   - **多行文字换行不一致**：不同行的换行规则不一致
   - **检查方法**：
     * 观察每行文字的结尾，看是否有单词被分割
     * 检查是否有连字符（-）出现在行尾，且下一行开头是单词的一部分
     * 检查换行是否破坏了语义完整性
     * 检查换行是否符合该语言的换行规范（如中文可以在任意位置换行，但英文单词不应在中间断开）

2. **文字超框/溢出** - 严重程度通常为 high
   - 文字内容超出容器的左边界、右边界、上边界或下边界
   - 文字被容器边缘切掉，部分内容不可见
   - 按钮、标签、卡片等组件内的文字溢出
   - 表格单元格内的文字溢出
   - 多行文字中某一行超出容器宽度
   - 检查方法：对比文字边界与容器边界，看是否有文字超出

3. **文字截断** - 这是重点检测项！严重程度通常为 high 或 medium
   - **【右侧裁切/容器过窄】**（极易漏报，必须重点查）：
     * 侧栏、菜单、列表项中，多条文字在**同一右边界**处结束，且可见部分像不完整英文单词（如 "Cov"、"Mont"、"Artic"、"Week"、"Read" 等短片段）→ 判为**文字截断**（容器宽度不足，右侧被裁切），严重程度 high。
     * 同一区域内多个标签/按钮文字均在右侧被齐边切掉 → 截断。
   - **字符顶部被截断**：字符的上半部分被切掉
     * 拉丁字母的上半部分（如 b, d, f, h, k, l, t 等）
     * 中文的上半部分（如 中、上、下、大、小 等）
     * 阿拉伯文、印度语系文字（如 Devanagari、Bengali、Tamil 等）的上半部分
     * 韩文（Hangul）的上半部分
     * 日文假名的上半部分
   - **字符底部被截断**：字符的下半部分被切掉
     * 拉丁字母的下半部分（如 g, j, p, q, y 等）
     * 中文的下半部分
     * 带下标的字符（如 H₂O 中的 ₂）
     * 复杂文字系统的下半部分
   - **字符左右两侧被截断**：字符的左右部分被切掉
   - **文字行尾被截断**：文字在行尾被截断（如 "测试..." 或显示不完整）
   - **多行文字中任何一行被截断**
   - **特别注意**：检查所有字符是否完整显示，特别是：
     * 复杂文字系统（阿拉伯文、印度语系文字、韩文、日文假名、泰文、缅甸文等）的字符完整性
     * 带变音符号、声调符号的字符是否完整（如 é, ñ, ü, ǎ, 等）
     * 上标、下标字符是否完整（如 x², H₂O, ¹²³ 等）
     * 多行文字中每一行的字符是否都完整
     * 检查字符的顶部、底部、左右边缘是否紧贴容器边界

4. **文字重叠** - 严重程度通常为 high
   - 多个文字或文字块相互重叠，导致内容不可读
   - 文字与图片、图标、按钮等其他元素重叠
   - 多行文字中行与行之间重叠
   - 文字与背景元素重叠导致可读性下降
   - 检查方法：观察文字之间是否有重叠区域，文字是否与其他UI元素重叠

5. **文字模糊** - 严重程度通常为 medium 或 low
   - 文字显示模糊不清，边缘不清晰
   - 文字有重影、锯齿或抗锯齿效果不佳
   - 文字颜色与背景对比度不足导致看起来模糊
   - 文字被缩放后质量下降
   - 检查方法：观察文字边缘是否清晰，是否容易阅读

6. **对齐问题** - 严重程度通常为 medium 或 low
   - **水平对齐不一致**：
     * 多行文字左对齐、右对齐、居中对齐不一致
     * 同一行的文字基线不对齐
     * 列表项的对齐不一致
   - **垂直对齐不一致**：
     * 多行文字的垂直对齐不一致
     * 文字行与行之间的基线未统一
     * 文字与图标、按钮的垂直对齐不一致
   - **混合对齐问题**：
     * 不同文字块的对齐方式不统一
     * 表格中单元格文字对齐不一致
   - 检查方法：观察文字的对齐基准线，看是否统一

7. **间距问题** - 严重程度通常为 low 或 medium
   - **字符间距问题**：
     * 字符之间间距过密，难以区分
     * 字符之间间距过疏，看起来不连贯
     * 不同区域的字符间距不一致
   - **行间距问题**：
     * 行间距过密，导致行与行之间难以区分
     * 行间距过疏，导致内容看起来分散
     * 不同段落的行间距不一致
   - **段落间距问题**：
     * 段落之间间距不合理
     * 段落间距不一致
   - **边距问题**：
     * 文字与容器边缘的间距不合理
     * 文字与其他元素的间距不合理
   - 检查方法：观察文字之间的间距是否均匀、合理

8. **乱码/编码问题** - 严重程度通常为 high
   - **占位符与乱码**：□、？、、空白块等无法识别的占位符
   - **形近字/错字显示**：该字与正确用字字形相近但实际错误（例如：应为"么"却显示成"厶"，应为"曰"却显示成"日"）
   - **部首、笔画错显**：某个字被显示成其部首或另一相似字形（如"么"显示成"厶"）
   - **特殊字符异常**：引号、破折号、省略号、空格等显示异常
   - **多语言异常**：应显示中文/英文等却出现方框、问号或乱码
   - **数字、符号异常**：数字、货币符号、表情符号等显示错误
   - **检查方法**：逐字对比"字形是否与正确用字一致"，而非"读起来是否通顺"；若有形近字错显（如 厶/么、日/曰、未/末），必须记为乱码/编码问题

9. **字体问题** - 严重程度通常为 low 或 medium
   - 字体大小不一致（同一区域使用不同大小的字体）
   - 字体样式不一致（如混用粗体、斜体、正常体）
   - 字体族不一致（如混用不同字体）
   - 字体与设计规范不符
   - 字体过小导致难以阅读
   - 字体过大导致布局问题
   - 检查方法：观察字体的一致性、大小是否合理

10. **UI 结构/布局问题** - 严重程度通常为 medium 或 high
   - 布局崩溃/错位、层级结构异常、容器结构异常、组件结构异常
   - 检查方法：从整体视角观察 UI 结构是否合理、层级是否清晰

**第十步：AI 对 UI 结构的整体判断（必须执行）**
- 在 structure_assessment 中明确写出对整体布局/层级的判断理由
- 若 structure_ok 为 false，必须在 issues 中至少有一条 "UI 结构/布局问题" 或合并到 summary

**特别强调**：
- 必须逐一检查上述所有10种问题类型，不能遗漏
- 必须仔细检查每个字符的完整性，特别是字符的顶部、底部、左右边缘
- 对于多语言内容，要特别注意复杂文字系统的字符完整性
- 如果发现任何问题，必须详细描述问题的具体位置、影响范围和严重程度
- 提供具体、可操作的修复建议

请按以下 JSON 格式返回检测结果：
```json
{
    "has_issues": true或false,
    "structure_ok": true或false,
    "structure_assessment": "AI 对 UI 结构的整体判断：布局是否合理、层级是否清晰、是否存在结构性问题。必须明确写出判断理由。",
    "issues": [
        {
            "type": "问题类型（必须从上述10种类型中选择，含'UI 结构/布局问题'；如果发现截断必须标记为'文字截断'，如果发现异常换行必须标记为'异常换行'）",
            "description": "问题描述（必须详细说明：具体位置、影响的字符/区域、问题的具体表现。如果是截断，必须明确指出哪个字符、哪个方向被截断）",
            "location": "位置描述（精确到具体行、区域、坐标或UI元素，如：第1行、左上角按钮、中间区域等）",
            "severity": "严重程度(high/medium/low，截断问题必须是high)",
            "suggestion": "修复建议（必须具体、可操作，如：调整容器高度、增加行间距、统一对齐方式等）"
        }
    ],
    "summary": "整体评估总结（必须包含：问题总数、主要问题类型、整体质量评估、AI 对 UI 结构的判断结论。如果发现截断，必须在总结中明确说明）",
    "score": 85
}
```

**⚠️ 重要：关于 score 字段**
- 如果发现任何截断问题，score 必须 < 80
- 如果发现乱码/形近字错显（如 厶/么、日/曰），score 必须 < 80
- 如果发现多处截断、严重截断或明显乱码，score 必须 < 60
- 如果 score 是 100 或接近 100，但图片中有截断或乱码，这是完全错误的检测结果

**评分标准（必须严格按照以下标准评分）**：
- **100分**：无任何问题，所有文字显示完美
- **90-99分**：有极轻微问题（如轻微的字体大小不一致、极轻微的间距问题），不影响使用
- **80-89分**：有轻微问题（如部分间距问题、轻微对齐问题），基本不影响使用
- **70-79分**：有明显问题（如部分截断、对齐不一致、部分间距问题），影响用户体验
- **60-69分**：有较多问题（如多处截断、多处溢出、部分重叠），严重影响用户体验
- **60分以下**：有严重问题（如大量截断、严重溢出、大量重叠、乱码），基本不可用

**严重程度判定标准**：
- **high（高）**：严重影响可读性或信息完整性，必须修复（如：截断、溢出、重叠、乱码）
- **medium（中）**：明显影响用户体验，建议修复（如：部分截断、对齐问题、模糊）
- **low（低）**：轻微影响美观或一致性，可选修复（如：轻微间距问题、字体大小不一致）

**系统化检测流程（必须按此顺序逐一检查）**：

**步骤1：字符完整性检查（已在上方详细说明，必须首先执行）**

**步骤2：乱码/形近字检查（防漏报重点）**
   - 逐字核对：图中字形是否与"在该语境下应有的正确用字"一致
   - **形近字错显**：如 厶/么、日/曰、未/末、土/士、己/已 等，若图中是错误字形，必须标记为"乱码/编码问题"，严重程度 high
   - **部首替字**：若某字被显示成其部首或另一相似部件（如"么"显示成"厶"），记为乱码
   - 不因"句子能读懂"而漏报，只看"每个字是否显示正确"

**步骤3：异常换行检查**
   - 检查每行结尾是否有单词被不恰当分割（如 "hel-\nlo"、"测-\n试"）
   - 检查是否有连字符（-）出现在行尾且下一行是同一单词的续写
   - 检查换行是否破坏语义完整性、是否符合该语言的换行规范

**步骤4：边界溢出检查**
   - 检查文字是否超出容器边界（左、右、上、下）
   - 检查按钮、标签、卡片等组件内的文字是否溢出
   - 检查表格单元格内的文字是否溢出

**步骤5：重叠检查**
   - 检查文字之间是否重叠
   - 检查文字与其他UI元素（图片、图标、按钮）是否重叠

**步骤6：对齐检查**
   - 检查水平对齐（左对齐、右对齐、居中）是否一致
   - 检查垂直对齐（基线对齐）是否一致
   - 检查不同文字块的对齐是否统一

**步骤7：间距检查**
   - 检查字符间距是否合理、一致
   - 检查行间距是否合理、一致
   - 检查段落间距是否合理、一致
   - 检查边距是否合理

**步骤8：显示质量检查**
   - 检查文字是否模糊
   - 再次核对是否有乱码、形近字错显（厶/么、日/曰等）
   - 检查字体大小、样式、字体族是否一致

**步骤9：综合评估**
   - 统计所有发现的问题
   - 评估整体质量
   - 给出综合评分

**输出要求（严格执行）**：

1. **如果发现截断问题**：
   - 必须明确指出：哪个字符、哪个方向（左/右/上/下）被截断
   - 严重程度必须是 high，得分必须 < 80
   - 必须提供具体的修复建议

2. **如果发现乱码/形近字错显**（如 厶/么、日/曰、未/末）：
   - 必须标记为"乱码/编码问题"，严重程度 high，得分必须 < 80
   - 必须写明：哪个字错显、正确应为哪个字、所在位置
   - 必须给出修复建议（如检查字体、编码、渲染）

3. **如果未发现截断、乱码问题**：
   - 必须确认：已逐字符检查，所有字符的四个边缘都完整
   - 必须确认：没有字符紧贴图片边界且不完整

3. **所有问题的描述必须包含**：
   - 具体位置（哪个字符、哪一行、哪个区域）
   - 具体表现（如何截断、如何溢出等）
   - 影响范围
   - 修复建议（必须具体、可操作）

5. **总结必须包含**：
   - 问题总数
   - 主要问题类型
   - 整体质量评估
   - 得分理由

**最终检查清单（在返回结果前必须确认）**：
- [ ] 已逐字符检查完整性（四个边缘）
- [ ] **已检查侧栏/列表/菜单**：多条文字是否在同一右边界处被齐边切掉（如 Cov、Mont、Artic 等短片段）→ 是则必记「文字截断」、high、降分
- [ ] 已逐字核对形近字/错显（如 厶/么、日/曰、未/末），有则记入乱码问题
- [ ] 已检查异常换行、溢出、重叠
- [ ] 已确认没有字符紧贴边界且不完整（或若有，已记截断）
- [ ] 若发现截断或乱码，得分已相应降低
- [ ] 所有问题描述已写清位置、表现、建议
- [ ] 未进行任何联想或推测

**🚨 最终警告：**
- 如果发现截断问题但得分是 100 分或接近 100 分，这是完全错误的检测结果，必须重新检查
- 截断问题必须标记为 high 严重程度
- 截断问题的得分必须相应降低（有截断不能是高分）
- 不要因为"可能是什么字"而忽略截断
- 不要因为"整体能理解"而忽略截断
- 只看图片中实际显示的内容，不要联想或推测

**现在开始检测（按顺序执行，且仅在有确定证据时记入问题）：**
1. 字符完整性检查（逐字符、四边缘）→ **仅当图中明确可见**截断时才记"文字截断"、high、降分。**必查**：侧栏/列表项中多条文字是否在同一右边界处被齐边切掉（如仅见 "Cov"/"Mont"/"Artic" 等短片段）→ 是则为右侧裁切截断。
2. 乱码与形近字检查（逐字核对 厶/么、日/曰 等）→ **仅当图中明确可见**错显时才记"乱码/编码问题"、high、降分
3. 异常换行检查 → **仅当图中明确可见**单词被分割、行尾连字符续写等时才记"异常换行"
4. 其余：溢出、重叠、对齐、间距、模糊、字体 → 同样**仅在有可见证据时**记入
5. 汇总：**无确定证据则不记入 issues**；summary 必须与 issues 一致（有则说有，无则说无）

请严格按上述流程执行，**只依据图片中实际可见、可指出的内容**，**禁止联想、推测、臆断**，并返回与证据一致的完整检测结果。
